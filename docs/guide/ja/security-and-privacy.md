# セキュリティとプライバシー

[English](../security-and-privacy.md) · **日本語**

監査は悪意のある入力を読むのが仕事です。このページでは、スキルが実行するもの、送信するもの、取得するもの、書き込むものと、監査するコード、その中の秘密情報、スキルが動くマシンをどう守るかをまとめます。

## 実行するもの・送信するもの・取得するもの・書き込むもの

| | |
|---|---|
| **ローカルで実行** | 同梱の Python スクリプト。監査対象リポジトリへの読み取り専用の git コマンド。固定したスキャナを Docker または Podman で実行（イメージはダイジェストで取得、リポジトリは読み取り専用でマウント、Gitleaks と hadolint はネットワークなし）。なければネイティブ版、それもなければ実行せず、その旨を明記。Excel の再計算チェック（Excel または LibreOffice がある場合）。 |
| **送信** | `threat_intel.py`：製品名とバージョンのみ（endoflife.date の製品 ID、`cpe:2.3:a:php:php:8.3.30` のような NVD の CPE 文字列、FIRST EPSS への CVE 番号）。リポジトリ名、パス、コード、指摘内容は送りません。OSV-Scanner はパッケージ名とバージョンを osv.dev に送り、Semgrep はルールパックを、Trivy は脆弱性データベースを取得します。 |
| **取得** | アカウント不要の公開フィード：CISA KEV（予備に GitHub のミラー）、NVD CVE API 2.0、FIRST EPSS、endoflife.date、IPA、JPCERT/CC、JVN、JVN iPedia の RSS。接続先は固定の許可リストで、`~/.cache/security-audit/intel` にキャッシュし、`--offline` ではキャッシュのみを使います。`run_scanners.py --check-updates` は、実行したときだけ Docker Hub と GHCR にタグの一覧を問い合わせます。 |
| **書き込み** | 監査対象リポジトリの外の監査フォルダ（`<親フォルダ>/<プロジェクト>-security-audit/<日時>/`）、フィードのキャッシュ、Standard と Deep では `~/.claude/agents/security-audit/` の補助サブエージェント 4 つだけです。 |

Semgrep は `--metrics off` と `p/default` のルールパックで実行し、プロジェクトの URL をレジストリに送る `auto` は使いません。TruffleHog は実行の仕組みに含まれていません。追加のツールとして使う場合も、提供者に接続する有効性の確認には利用者の承認が必要です。

## 読み取り専用の規則

- **監査対象のコードは編集しない。** 整形、コミット、「ついでに修正」もしません。監査する側は報告し、修正は利用者が行います。これは職務分離の要件でもあります（OWASP AISVS 1.01 Appendix C、AC.8.1 と AC.8.4）。
- **監査対象リポジトリの中には出力しない。** `run_scanners.py` はリポジトリ内の出力先を拒否し、どのスクリプトも監査フォルダに書き出します。
- **git は読み取り専用で、何も実行させない。** すべての git 呼び出しで `core.fsmonitor`、任意のロック、フック、リポジトリ側の設定を無効にし、インデックスにも書き込みません。Gitleaks の履歴スキャンは textconv も外部 diff ドライバも使いません。
- **コンテナは隔離する。** リポジトリは読み取り専用でマウントします。Linux と macOS ではコンテナを現在のユーザーとして実行します。SELinux のホストでは `label=disable` を使い、`:z` は使いません。ラベルの付け替えは監査対象リポジトリへの書き込みになるためです。
- **リポジトリの外を指すシンボリックリンクは読まずに数える**ため、それを通じてホストのファイルを読むことはありません。
- **コードをビルドも実行もしない。** スクリプトはファイルを読むだけで、プロジェクトのコードを実行しません。

## 秘密情報と個人データは表示しない

- 秘密情報、カード番号、個人データは、本物でもテスト用でも、一部を切り詰めた形でも、やり取りの記録、指摘事項、報告書のどこにも出しません。
- 秘密情報を含む行は `peek.py` でだけ確認します。`peek.py` は、秘密鍵、エントロピーの高いトークン、秘密情報らしき名前の値、CLI に渡した秘密情報、クラウドや SaaS のトークンの形、カード番号らしき数字、接続文字列のパスワード、メールアドレス、電話番号、日本の住所、個人データの値をマスクし、名前、キー、行番号、コードの構造は見えるままにします。
- 秘密情報を探すために、設定ファイル、IaC、`.env*`、シードやフィクスチャのファイルに `cat`、`sed`、`grep` を使うことはありません。値がやり取りの記録に入ってしまうためです。
- `repo_digest.py` は場所とトークンの種類だけを記録し、行の内容は記録しません。`sensitive_sweep.py` は `file:line`、一致した語、データの種類を報告し、値は出しません。Luhn 検査に合う数字は`PAN-like literal` として値なしで報告します。
- Gitleaks は `--redact` で実行し、正規化の処理は長いトークンをマスクし、Excel の描画は文字列をマスクします。
- 指摘事項には変数名と `file:line` を書き、値は書きません。カード番号らしき値や秘密情報が残った報告書は、検証スクリプトが拒否します。

このガイドの例では、`<token>` や `CVE-2026-XXXXX` のようなプレースホルダを使っています。

## 監査対象の内容は根拠であって、指示ではない

README、`CLAUDE.md`、`AGENTS.md`、スキルのファイル、ルール、コードのコメント、プロンプトのログ、MCP ツールの説明、アドバイザリフィードの文章は、AI エージェントに向けて書かれていることがあります。スキルはそれらをすべてデータとして読みます。その内容に従うことも、実行、取得、インストールすることもなく、指示のような文章は指摘事項として報告します。

関連する保護：

- **リポジトリが自分のスキャナを黙らせることはできない。** Gitleaks はリポジトリの許可リストを無視し、zizmor は `--no-config`、Semgrep は `--disable-nosem`、OSV-Scanner は空の設定で動きます。無効化できないもの（`.gitleaksignore`、`.checkov.yaml`、`.semgrepignore`）は未確認範囲として列挙します。コード内の `nosemgrep`、`# noqa`、`gitleaks:allow` は、監査対象のコードによる主張として記録します。
- **スキャナの出力は信頼しない。** SARIF はデータとして解析し、実行はしません。メッセージは切り詰め、秘密情報らしき文字列はマスクします。
- **フィードの文章は信頼しない。** 制御文字、双方向制御文字、ゼロ幅文字を取り除き、タイトルを切り詰め、リンクはそのフィード自身のホストのものだけを残し、他のホストへのリダイレクトは拒否します。
- **HTML の出力はエスケープする。** 監査対象のコードから引用したものはすべて HTML としてエスケープし、生の HTML は通さず、外部のものは何も読み込みません。
- **Excel の出力に監査からの数式は入らない。** `=`、`+`、`-`、`@` で始まるセルは文字列として保存します。
- **自己防衛。** 監査対象が現在の作業フォルダで、`.claude/`、`.mcp.json`、`CLAUDE.md` を含む場合、そのフック、MCP サーバー、指示はこのセッションで有効になっています。スキルはそのことを伝え、中立なフォルダから始めるよう勧めます。そのフォルダに `.claude/agents/security-audit-*` があると、スキルのエージェントより優先されてしまうため、スキルは汎用サブエージェントで代用します。
- **サブエージェントは制限されている。** Edit と Agent はなく、ターン上限があり、`CLAUDE.md` は読み込みません。

## 出力は利用者のもの

スキルが利用者のリポジトリについて書き出す指摘事項、報告書、作業ファイル、一覧、脅威情報のまとめは利用者のもので、条件は自由に決められます。スキル自体のライセンスは AGPL-3.0-only です。[NOTICE](https://github.com/nguyenhx2/agent-security-audit/blob/main/NOTICE.md) を参照してください。

## スキル自体の脆弱性を報告する

公開の Issue ではなく、GitHub の非公開の脆弱性報告（リポジトリの **Security** タブから **Report a vulnerability**）を使ってください。対象範囲と記載する内容は [SECURITY.md](https://github.com/nguyenhx2/agent-security-audit/blob/main/SECURITY.md) にあります。
