# security-audit 利用ガイド

[English](../index.md) · **日本語**

`security-audit` は、Claude Code 用の読み取り専用セキュリティ監査スキルです。1 つ以上のリポジトリを指定すると、技術スタックと業種を特定し、バージョンを固定したスキャナを実行し、デプロイしているものを今日公開された脆弱性情報と照合し、スキャナに見えない欠陥をモデルに探させ、すべての指摘の反証を試みたうえで、検証済みの指摘事項と報告書を Markdown・HTML・Excel で、英語、日本語、またはその両方で書き出します。

監査対象のコードを編集、ビルド、実行することはありません。出力はすべてリポジトリの隣のフォルダに置き、修正は利用者が行います。

## 対象となる利用者

- **開発者**：リリース前に自分のリポジトリのセキュリティレビューをしたい、あるいは「この CVE の影響を受けるか」に答えたい方。
- **セキュリティエンジニア**：Web と API のバックエンド、モバイルアプリ、IaC、CI/CD パイプライン、AI エージェントをレビューし、バージョン付きの基準を引用して `file:line` を示す指摘事項が必要な方。
- **規制のある業種のチーム**：医療、金融と暗号資産、EC、公共、教育、IoT・OT・車両の分野で、OWASP だけでなく日本、米国、EU、ベトナムの規則を適用する必要がある方。

修正を適用するためのツールではなく、現在の差分だけをレビューするためのものでもありません。差分のレビューには Claude Code の `security-review` を使ってください。

## 2 つの強み

### 監査の時点で最新の脅威情報

ロックファイルのスキャナが答えられるのは「依存しているパッケージに脆弱性があるか」だけです。しかし多くのインシデントは別の所から始まります。インタープリタや Web サーバーのリリース、公開されたままの管理ツールや BI ツール、Web ルートの下に置かれたファイルなどです。どの監査でも、どの深さでも、`platform_inventory.py` がリポジトリが実際にデプロイしているもの（ベースイメージ、ランタイム、サーバー、データストア、管理ツール）を読み、`threat_intel.py` がその時点で取得した <!--n:feeds-->8<!--/n--> つのフィード（CISA KEV、NVD、FIRST EPSS、endoflife.date、IPA、JPCERT/CC、JVN、JVN iPedia）と照合します。新しいインシデントも、名前を指定しなくても対象になります。取得に失敗したフィードは報告書に未確認範囲として明記し、合格扱いにはしません。詳しくは[ライブ脅威情報](threat-intelligence.md)を参照してください。

### 定期的に、安全に更新され、勝手に切り替わらないスキャナ

<!--n:scanners-->8<!--/n--> 種のスキャナは、バージョンと SHA-256 ダイジェストで固定したイメージから実行します。そのため同じコードを 2 回監査すれば結果は一致し、再スキャンでは欠陥を見つけたのと同じルールで修正を判定します。新しいバージョンは毎週のワークフローで取り込みます。リリースから 7 日待ち、仕込んだ欠陥を今も検出できることを確かめてから、メンテナが手でマージするプルリクエストを作成します。監査がスキャナを勝手に切り替えることはありません。詳しくは[スキャナ](scanners.md)を参照してください。

## すぐに試す

```text
/plugin marketplace add nguyenhx2/agent-security-audit
/plugin install security-audit@agent-security-audit
```

続いて Claude Code で、監査したいリポジトリの外のフォルダから次のように入力します。

```text
../shop-api をセキュリティ監査して
```

スキルが深さ、報告書の言語、重点領域、形式を確認し、最後まで実行します。詳しくは[初めての監査](first-audit.md)を参照してください。
