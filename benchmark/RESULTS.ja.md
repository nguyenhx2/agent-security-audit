# ベンチマーク結果

意図的に脆弱にした 3 つのプロジェクトを、ヘッドレスの Claude Code で実際に監査し、security-audit 1.13.0 と
1.15.0 を比べた結果です。方法、正解の定義、再現手順は [`README.md`](README.md) にあります。生データは
[`results/results.json`](results/results.json) です。[English](RESULTS.md)

## 条件

- フィクスチャは [`fixtures.json`](fixtures.json) で固定：DVWA、NodeGoat、OWASP Juice Shop。
- 深さは Quick。プロンプトは `/<skill> <repo> quick --yes` と「Report language: English. Formats: Markdown only.」。
  実行ごとの予算上限は両バージョンで同じです。
- バージョンとフィクスチャの組み合わせごとに 3 回、合計 18 回、費用の合計は US$41.71 です。
- Claude Code CLI は、1.13.0 の実行（2026-10-26）が 2.1.310、1.15.0 の実行（2026-10-27）が 2.1.311 です。
  2 日の間に CLI が自動更新されました。モデルは CLI の JSON 出力の記録どおり、どちらも
  `claude-opus-5-5` です。
- 1 台の Windows 11 マシンで最大 3 つの監査を同時に実行したため、所要時間には競合の影響が含まれます。
  費用、ターン数、指摘数、再現率はその影響を受けません。

## 変わったこと、変わらなかったこと

- **再現率。** 1.15.0 は DVWA と Juice Shop で、文書化された種類をより多く見つけました。NodeGoat はどちらも
  100% です。DVWA での向上の大部分は、新しいプラットフォーム棚卸しと脅威情報の手順が対象とする、サポート終了の
  ランタイムの種類（3 回中 3 回、1.13.0 は 3 回中 1 回）です。Juice Shop では、複数のインジェクションと SSRF の種類に
  分散しています。
- **脅威情報。** 1.15.0 のすべての報告書に「プラットフォームのバージョンと脅威情報」の章があります。1.13.0 には
  この手順がありません。
- **費用。** 監査 1 回あたりはほぼ同じです（平均で +4%）。1.15.0 は最も大きい Juice Shop で多く、DVWA と
  NodeGoat で少なく使っています。
- **所要時間。** 平均では 1.15.0 が 30% 短いものの、その大半は 1.13.0 の遅い 2 回（26 分と 18 分。3 つの監査が
  同じマシンを共有した最初の実行）によるものです。中央値の差は約 1 分です。
- **測定していないもの。** 適合率です。これらのプロジェクトには文書化されている以上の不具合があるため、10 種類
  以外の指摘を誤検知と判断するには、人が読んで確認する必要があります。

## このベンチマークの経緯

上の数値を、それ以前に起きたことと合わせて判断できるように記録します。

1. **リリース候補（2026-10-26）。** 最初の 1.15.0 ビルドを同じフィクスチャで実行しました。9 回のうち 8 回は
   完了し、1 回（DVWA の 3 回目）は 4 分、US$1.56 で、指摘事項を 1 件も書かずに止まりました。ヘッドレス
   実行では誰も答えられない質問をするために、モデルが一時停止したためです。これを受けて、最終版の 1.15.0 の
   SKILL.md に「最後まで実行する」（Phase 0 の後は止まらずに報告書まで進める）を追加しました。リリース候補の
   実行は上の表に含めていません。
2. **中断された実行。** 2 回、実行の途中でバッチが止まりました（メモリ不足、その後は手動停止）。こうして途中で
   切れた実行は、結果がないか中断の結果を返したため、削除して実行し直しました。上の表には含まれていません。
   現在の `bench.py` は、このような実行を結果として保存しないため、再開したベンチマークは 0 件として数えずに
   実行し直します。
