# ベンチマーク結果

意図的に脆弱にした 3 つのプロジェクトを、ヘッドレスの Claude Code で実際に監査し、security-audit 1.15.0 と
1.15.2 を比べた結果です。方法、正解の定義、再現手順は [`README.md`](README.md) にあります。生データは
[`results/results.json`](results/results.json) です。以前の 1.13.0 と 1.15.0 の比較は、下の
「[以前の比較](#以前の比較1130-と-1150)」に残しています。[English](RESULTS.md)

## 条件

- フィクスチャは [`fixtures.json`](fixtures.json) で固定：DVWA、NodeGoat、OWASP Juice Shop。
- 深さは Quick。プロンプトは `/<skill> <repo> quick --yes` と「Report language: English. Formats: Markdown only.」。
  実行ごとの予算上限は両バージョンで同じです。
- バージョンとフィクスチャの組み合わせごとに 3 回、合計 18 回、費用の合計は US$44.92 です。すべて 2026-10-30 に実行しました。
- Claude Code CLI はすべての実行で 2.1.314、モデルは CLI の JSON 出力の記録どおり `claude-opus-5-5` です。
  1.15.0 は `v1.15.0` タグのチェックアウトを `sa-v1150` として、1.15.2 はリリースのコミットを `sa-v1152` として
  インストールして実行しました。
- 1 台の Windows 11 マシンで 2 つの監査を同時に実行したため、所要時間には競合の影響が含まれます。
  費用、ターン数、指摘数、再現率はその影響を受けません。

## この実行の目的

1.15.2 はパッチリリースです。1.15.1 の検出の修正（OpenAI SDK v3、`shop` というキーワード、fetch ハンドラのルート解析、
Express の目印）、新しいスキャナの固定バージョン、`--check-updates` オプション、ReDoS の修正を含みます。
どれもモデルが欠陥を探す手順は変えません。確かめたいのは、何かが悪くなっていないかです。

## 変わったこと、変わらなかったこと

- **再現率。** DVWA と NodeGoat は同じです（12 回すべてで 100%）。Juice Shop では、1.15.2 の見逃しが延べ 3 件
  （XSS が 2 回、path traversal が 1 回。いずれも 1 回目と 2 回目）、1.15.0 は 1 件でした。1.15.2 の 3 回目は
  10 種類すべてを見つけています。Juice Shop の XSS は 1.15.0 でも最も弱い種類で（以前の比較では 3 回中 1 回、
  今回は 3 回中 2 回）、1.15.2 はレビューの手順に手を入れていないため、退行ではなく実行ごとのばらつきと
  読めます。ただし各条件 3 回では、それを否定しきれません。
- **サポート終了のランタイムと脅威情報。** 両バージョンとも、DVWA と NodeGoat の 6 回すべてで検出しました。
  両バージョンのすべての報告書に「プラットフォームのバージョンと脅威情報」の章があります。
- **費用。** 監査 1 回あたり US$2.52 と US$2.47（+2%）で、どちらのバージョンのばらつきの範囲内です。1.15.2 は
  DVWA で多く（主に US$3.11 の 1 回）、NodeGoat と Juice Shop で少なく使っています。
- **所要時間。** どちらも監査 1 回あたり約 8 分です。中央値は 7.3 分と 7.7 分です。
- **測定していないもの。** 適合率です。これらのプロジェクトには文書化されている以上の不具合があるため、10 種類
  以外の指摘を誤検知と判断するには、人が読んで確認する必要があります。

## この実行についての補足

- **上の数値の前に直した採点の不具合。** `sa-v1152_DVWA_3` は最初、指摘数 0 と採点されました。モデルが出力
  ディレクトリの中に `snapshot-<日付>_<時刻>` という補助フォルダを作ってプロジェクトを複製し、その複製を監査
  したためです。`bench.py` は名前順で最後のフォルダを読んでいたため、監査結果ではなくこの複製を選んでいました。
  現在の `bench.py` は、タイムスタンプ名の監査フォルダだけを読みます。採点し直した結果は、指摘数 29、再現率
  100%、検証合格、脅威情報の章ありです。複製には git の履歴がなかったため、この実行の秘密情報の履歴スキャンは
  限られた範囲になりました。
- **同じ実行のフィード。** CISA KEV の一覧は 79 時間前のキャッシュから読み、JVN iPedia は応答しませんでした。
  スキルの決まりどおり、報告書には両方が記載されています。

## このベンチマークの経緯

上の数値を、それ以前に起きたことと合わせて判断できるように記録します。

1. **リリース候補（2026-10-26）。** 最初の 1.15.0 ビルドを同じフィクスチャで実行しました。9 回のうち 8 回は
   完了し、1 回（DVWA の 3 回目）は 4 分、US$1.56 で、指摘事項を 1 件も書かずに止まりました。ヘッドレス
   実行では誰も答えられない質問をするために、モデルが一時停止したためです。これを受けて、最終版の 1.15.0 の
   SKILL.md に「最後まで実行する」（Phase 0 の後は止まらずに報告書まで進める）を追加しました。リリース候補の
   実行は上の表に含めていません。
2. **中断された実行。** 何度か、実行の途中でバッチが止まりました（メモリ不足、手動停止、2026-10-30 には 1.15.2 が
   できる前に 1.15.1 を比べようとした最初の試行）。こうして途中で切れた実行は、結果がないか中断の結果を返した
   ため、削除して実行し直しました。表には含まれていません。`bench.py` は、このような実行を結果として保存しない
   ため、再開したベンチマークは 0 件として数えずに実行し直します。
3. **監査フォルダの選び方（2026-10-30）。** 上の「この実行についての補足」を参照してください。
