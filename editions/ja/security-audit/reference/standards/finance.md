# モジュール：finance - 銀行、決済事業者、証券、暗号資産

コードが資金や金融上のポジションを移動または記録する場合に適用する（detect の業種 `finance` /
`crypto`：銀行口座、振込、元帳、ウォレット、全銀フォーマット、オープンバンキング API、暗号資産の
ライブラリ）。カードデータそのものは `reference/standards/pci-dss.md` が扱う。このモジュールは金融分野の
規則を上乗せする。バージョンは `reference/standards/index.md` に従う。

## 目次
1. 適用される規則

## 1. 適用される規則
| 正規名 | 内容 | 版 / 日付 | 対象 |
|---|---|---|---|
| `FISC Security Guidelines` | 金融機関等コンピュータシステムの安全対策基準・解説書（FISC） | 第14版、2026-03 | 日本の銀行、証券、保険会社とそのシステムベンダー（事実上の標準。金融庁の検査で参照される）。構成：統制基準 / 実務基準 / 設備基準 / 監査基準。本文は有償：版 + 基準の区分を引用し、本文を引用（転載）しない。第14版で AI の利用と耐量子計算機暗号への備えが追加された |
| `FSA Cybersecurity Guidelines` | 金融分野におけるサイバーセキュリティに関するガイドライン（金融庁、別紙18） | 2024-10-04、技術的な改正 2025-07-04 | 金融庁が監督するすべての金融機関。項目は「基本的な対応事項」または「対応が望ましい事項」 |
| 金融庁 事務ガイドライン 16 + JVCEA の規則 | 暗号資産交換業者の資産管理とシステム管理態勢 | JVCEA のシステム管理態勢に関する規則は 2026-07-01 施行。暗号資産は金融商品取引法の対象へ移行（改正法は 2026-07-15 成立、1 年以内に施行） | 日本の暗号資産交換業者 |
| `GLBA Safeguards Rule` | 16 CFR 314（FTC） | 2023 年改正。2024-05-13 から、500 人以上の消費者に影響する場合は 30 日以内に FTC へ通知 | 米国の銀行以外の金融機関 |
| `NYDFS 23 NYCRR 500` | ニューヨーク州金融サービス局のサイバーセキュリティ規則（第 2 次改正） | 最終段階 2025-11-01（全利用者への MFA、資産台帳） | ニューヨーク州の免許を持つ金融サービス |
| `Vietnam Circular 09/2020/TT-NHNN` + `Vietnam Circular 50/2024/TT-NHNN` | 銀行の IT セキュリティ。オンラインバンキングサービスのセキュリティ | 09/2020 は施行中（一部改正）。50/2024 は 2025-01-01 から | ベトナムの銀行とそのアプリ |
このほか、カードデータには `PCI DSS`、顧客データには `Japan APPI` / マイナンバー、EU の事業体には DORA（EU）。

## 2. コードから根拠を示せる確認項目
| ID | 確認項目 | 検証する内容 | 金融庁ガイドラインの項目 | 検出 |
|---|---|---|---|---|
| F01 | 元帳の完全性 | 残高は追記専用の仕訳によってのみ変わる。元帳テーブルに直接の `UPDATE balance` や `DELETE` がない。照合ジョブがある | 2.3.3 | M |
| F02 | 冪等性と原子性 | 振込、出金、払い出しは冪等性キーを受け取り、行ロックまたはバージョン管理のもとで 1 つのトランザクションで実行し、リトライで二重実行されない | - | M |
| F03 | 特権アクセスと職務の分離 | 資金移動や限度額の変更には管理者 / 運用者の操作に第 2 の承認者が必要（メーカー・チェッカー）。共有の管理者アカウントがない。開発者のロールから本番データに到達できない | 2.3.1 | M |
| F04 | 認証 | 顧客には取引金額に応じた MFA またはリスクベース認証。すべての特権アクセスとリモートアクセスに MFA。既定のパスワードがない。API に埋め込まれた認証情報が管理されローテーションされている | 2.3.1 | S+M |
| F05 | 暗号 | データは分類に応じて CRYPTREC の電子政府推奨暗号リストのアルゴリズムで暗号化する。鍵は KMS / HSM にある。至る所に RSA / ECDH をハードコードするのではなく、アルゴリズムの移行を可能にする暗号の台帳または抽象化層がある（FISC 第14版の耐量子計算機暗号への備え） | 2.3.3 | S+M |
| F06 | ログ | セキュリティログと取引ログが改ざんから保護され（WORM、ログファイルの検証）、アクセス制御され、定められた期間保持される | 2.3.4.2 | S+M |
| F07 | バックアップ | 隔離され、変更不可で、復元テスト済みのバックアップ（Object Lock、Backup Vault Lock、別アカウントへのコピー） | 2.3.3 | S |
| F08 | 脆弱性と資産の管理 | CI で SBOM を生成し、依存関係の更新を自動化し、EOL のランタイムを追跡する（`intel.md`）。CI で SAST を実行する | 2.2.1、2.2.3、2.3.4.3 | S |
| F09 | ネットワークと環境 | 外部 / 内部の分離、最小限の許可ルール、開発とテストの本番からの分離、リモートアクセスのセッションタイムアウトとログ | 2.3.4.4 | S+M |
| F10 | モバイルバンキングアプリ | root / 脱獄の検知、証明書のピン留め、端末の紐付け、高額送金での生体認証または Smart-OTP（Vietnam Circular 50/2024。他の地域でも良い慣行） | - | S+M |
オープンバンキング / 電子決済等代行業の API ではさらに：口座ごとの OAuth スコープ、同意の記録、トークンの紐付け、レート制限。

## 3. 暗号資産の管理（日本の交換業者、および顧客資産を預かるすべてのウォレット）
| ID | 確認項目 | 検証する内容 |
|---|---|---|
| C01 | ホット / コールドの分離 | 出金の署名は上限のあるホットウォレットからのみ行う。顧客資産はオフラインのコールドストレージへ移す。コールドの鍵をオンラインで読み込むコード経路がない |
| C02 | 単独の署名者がいない | マルチシグ、MPC、閾値署名。単独で署名できるサービスアカウントや鍵がない。ブロードキャスト前の承認ワークフロー（2024 年の DMM Bitcoin の事案では 1 人での署名が問題として指摘された） |
| C03 | 鍵の保管 | 秘密鍵、シード、xprv をコード、env ファイル、CI 変数、ログに決して置かない。HSM / KMS / カストディ事業者のポリシーエンジン |
| C04 | 出金の管理 | アドレスの許可リスト、頻度と金額の上限、高額または新規アドレスへの出金の遅延、異常のアラート、緊急停止 |
| C05 | 第三者のウォレット SDK | バージョンの固定、Webhook の署名検証、スコープと IP を制限した API キー（外部のウォレットシステム経由の流出も 2024 年に指摘された） |
| C06 | 分別管理 | 顧客の残高と自己の残高を別々の元帳で管理し、照合する |

## 4. 重大度
- **P0：** 認可や承認なしに資金や暗号資産を移動させる経路。コード、設定、CI から到達できる署名鍵や
  シード。API 経由で編集できる元帳の行。
- **P1：** 払い出しや振込に冪等性がない。承認者 1 人だけの資金移動。アプリサーバーを掌握した攻撃者が
  書き換えられるログやバックアップ。特権アクセスに MFA がない。
- **P2：** SBOM / 暗号の台帳がない。IaC で開発と本番が分離されていない。少額のエンドポイントに
  レート制限がない。

## 5. 引用の注記
FISC：`FISC Security Guidelines 14th 実務基準`（基準の区分の単位。本文が有償のため項番は未検証）。
金融庁：`FSA Cybersecurity Guidelines 2024 2.3.1`（項番は別紙18 による）。それぞれに検証可能な管理策
（`OWASP ASVS 5.0.0`、`PCI DSS v4.0.1`、CWE）を組み合わせる。
