# モジュール：ecommerce - EC サイト、マーケットプレイス、カード決済を受け付ける加盟店

コードが EC サイトやマーケットプレイスを運営している場合に適用する（detect の業種 `ecommerce`：カート、
注文、配送、EC プラットフォーム、3-D セキュア、決済代行事業者の決済画面）。カードデータの規則は
`reference/standards/pci-dss.md` が扱う。このモジュールは加盟店側の規則を上乗せする。バージョンは
`reference/standards/index.md` に従う。

## 1. 適用される規則
| 正規名 | 内容 | 版 / 日付 | 対象 |
|---|---|---|---|
| `Japan Credit Card Security Guidelines` | クレジットカード・セキュリティガイドライン（クレジット取引セキュリティ対策協議会）。経済産業省は割賦販売法のセキュリティ義務の実務上の基準として扱う | 6.1版、2026-03-11（実質的な変更は 2025-03-04 の 6.0版） | 日本でカード決済を受け付けるすべての加盟店と、その決済代行事業者 / EC プラットフォームのベンダー |
| `PCI DSS` | カードデータのセキュリティ | v4.0.1 | カードデータを保存、処理、伝送するすべての事業者 |
| `Vietnam E-commerce Law` | Law 122/2025/QH15 + Decree 248/2026/ND-CP | 2026-07-01 施行 | ベトナムの EC サイトとプラットフォーム |

## 2. コードから根拠を示せる確認項目（特記がなければ日本のガイドライン 6.x）
| ID | 確認項目 | 検証する内容 | 検出 |
|---|---|---|---|
| E01 | カード情報の非保持化 | カード番号が加盟店のサーバーで保存、処理、通過されることが決してない：トークン、iframe、リダイレクト、JavaScript 型の決済代行フロー。PAN のカラム、ログ内の PAN、カード番号を運ぶサーバー側のフォーム項目がない | S+M |
| E02 | 決済画面の完全性 | JavaScript 型のフローではスキマーが非保持化を無効にする：スクリプトの読み込み元を制限する CSP、第三者スクリプトへの SRI、決済画面の改ざん検知、管理者が書き換え可能なテンプレートを決済画面で配信しない | S+M |
| E03 | 管理画面の保護（脆弱性対策 1） | 管理画面には IP の許可リストまたは VPN からのみ到達できる。管理者ログインに MFA。既定のアカウントや共有アカウントがない。既定ではない管理パス。Basic 認証だけでは不十分 | S+M |
| E04 | データディレクトリを露出させない（対策 2） | ディレクトリ一覧表示がない。`/upload`、`/backup`、`.git`、`.env`、`*.sql` を配信しない。ストレージのバケットが非公開（`platform.md` のシグナル） | S |
| E05 | Web アプリケーションの脆弱性（対策 3） | SQLi、XSS、OS コマンドインジェクションが修正済み。EC プラットフォームとプラグイン（EC-CUBE、WordPress / WooCommerce、Magento）にパッチが適用済み - `intel.md`。CI で SAST / DAST と依存関係の更新 | S+M |
| E06 | マルウェア対策と改ざん検知（対策 4） | IaC やイメージにおけるサーバー側のマルウェア対策 / EDR と、Web ルートのファイル完全性監視 | S |
| E07 | クレジットマスターなどのカード不正利用への対策（対策 5） | IP、端末、カードごとのオーソリ試行回数のレート制限。決済画面での CAPTCHA またはボット検知。オーソリ失敗回数の上限 | M |
| E08 | EMV 3-D セキュア | 決済代行事業者との連携ですべての EC 取引に 3DS2 が有効（2025 年 3 月末から原則必須）。全面的に無効化されたり「attempt only」になっていたりしない | S+M |
| E09 | ログイン時の不正対策（6.0版で新設） | 会員登録、ログイン、属性変更の各時点で、次のうち少なくとも 1 つ：MFA / 2 段階認証、パスキー、試行回数の制限とロックアウト、デバイスフィンガープリント / リスクベースのログイン、変更通知メール。3 つの時点のいずれかで欠けていれば指摘事項とする | M |
| E10 | アップロードの扱い | 拡張子と Content-Type の許可リスト、アップロード先ディレクトリでの実行禁止、Web ルート外への保存（EC サイトのセキュリティ対策チェックリストより） | S+M |
| E11 | ベトナム：運営規約の公開、出品者の確認、購入者データの保護、許可を受けた決済仲介事業者、商工省への届出バッジ | サイトのフッター / ページ、出品者の登録フロー、決済連携 | M |

## 3. 重大度
- **P0：** 加盟店のサーバーやログにカード番号がある。攻撃者または管理者テンプレートが検知されずに
  スクリプトを注入できる決済画面。顧客データを持つ管理画面が MFA なしでインターネットに公開されている。
- **P1：** 3-D セキュアが無効。カード不正利用の制限がない。3 つの時点のいずれかでログイン時の不正対策が
  ない。KEV / 注意喚起の対象 CVE を持つ未パッチの EC プラットフォーム。
- **P2：** 改ざん検知やファイル完全性監視がない。実行経路のない、弱いアップロード制限。

## 4. 検出のヒント
決済代行事業者の SDK（GMO-PG、SBPS、VeriTrans、Paygent、ZEUS、Stripe、PAY.JP、KOMOJU、Adyen、Braintree）、
EC プラットフォーム、テーブル `orders` / `cart` / `payment`、ルート `/checkout` `/cart` `/mypage` `/admin`、
用語 `3ds`、`tds2`、`本人認証`。
