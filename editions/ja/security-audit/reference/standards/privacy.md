# モジュール：privacy - データ保護法および業界別法令（コードからの根拠に基づく）

システムが個人、アカウント、健康、生体、または子どものデータを保存する場合に適用する。適用される
法域はスコーピングの質問（Phase 0）で選択する - 決して推測で決めない。コード監査が根拠を示せるのは
*技術的*義務のみであり、法的根拠、契約、DPIA は静的監査の範囲外である（その旨を明記する）。
`<law> <article>` の形式で、法令の正式な識別子を用いて引用する。例：`GDPR Art. 32`、
`Vietnam PDPL 91/2025/QH15 Art. <n>` - 正確な条番号に確信がない場合は、推測せず、
条番号なしで義務と法令を引用する。

## コードで確認する技術的義務

| 義務 | 検証内容 | 場所 / grep のヒント |
|-----------|----------------|--------------------|
| 処理のセキュリティ（GDPR Art. 32、APPI の安全管理措置、PDPL の保護措置、HIPAA 164.312） | 個人データの保存時/通信時の暗号化。アクセス制御。監査ログ | `reference/method/sensitive-data-at-rest.md`、owasp-web A01/A04 |
| データ最小化 / 目的の限定 | 必要なフィールドのみ収集/保存。ID で足りる箇所でレコード全体を複製しない。分析用ペイロードは最小限 | DTO、分析用 `track(` のペイロード、ログ |
| 保存の制限 / 保持期間 | TTL、保持ジョブ、論理削除行のパージ、バックアップ方針 | パージのない `deleted_at`、保持ジョブなし |
| 消去 / アカウント削除（GDPR Art. 17、CCPA の削除、PDPL の削除権） | 「アカウント削除」が、すべてのテーブル、キャッシュ、検索インデックス、オブジェクトストレージ、第三者（決済事業者の顧客情報、CRM、分析）にわたり個人情報を削除または匿名化する | アカウント削除ハンドラ：すべての FK と副次ストアを追跡する |
| アクセス / ポータビリティ（DSAR） | エクスポート経路が存在し、すべてのストアを網羅。エクスポートに認可（本人のデータのみ） | エクスポート用エンドポイント |
| 同意 | トラッキング/分析/マーケティング SDK は同意後にのみ初期化。同意はタイムスタンプ/バージョンとともに記録 | SDK の初期化順序、Cookie バナー、モバイルの ATT |
| 特別な種類 / 機微データ（健康、生体、子ども、国民 ID、APPI の「要配慮個人情報」、PDPL の「sensitive personal data」） | 追加の保護（暗号化、アクセスログ、別ストア）。法的根拠を明示 | `sensitive_sweep.py` のクラス health-PHI、biometric、national-id-PII |
| 越境移転（PDPL、PIPL、APPI、GDPR Ch. V） | データの送信先：第三者 API、クラウドリージョン、LLM プロバイダ。移転が記録されている | 外向き SDK、リージョン設定、プロンプトに個人情報を含む LLM 呼び出し |
| 侵害の検知と通知の支援（GDPR 72h、PDPL 72h、APPI 第26条 速やかに + 30 日 / 60 日、CRA Art. 14 24h early warning） | 侵害を検知し範囲を特定できるだけのセキュリティイベントのログ | owasp-web A09 |
| 子どものデータ | 製品が未成年を対象とする場合の年齢確認 / 保護者同意の経路 | 登録フロー |

## 法域ごとの注記
- **Vietnam PDPL：** 機微な個人データ（sensitive personal data）には健康、生体、金融/銀行口座、
  位置情報、犯罪歴などが含まれる - 保存された銀行/カードデータは PCI の範囲外であっても機微データとして扱う。
- **Japan APPI（個人情報の保護に関する法律）**（条番号は 2022 年の施行以降のもの。2026 年改正（Act No. 56 of
  2026）は条番号を変えない）：
  - 第20条第2項：要配慮個人情報（病歴、健康診断の結果、障害、人種、信条、犯罪の経歴）の取得には本人の
    事前の同意が必要 - そうした項目を保存する前に同意の手順があることを確認する。
  - 第23条：安全管理措置 - 個人データの暗号化、アクセス制御、ログについて引用する条文。第24条-第25条：
    従業者と委託先の監督。
  - 第26条：個人情報保護委員会への漏えい等の報告と本人への通知。施行規則 第8条第1項：速やかな速報
    （個人情報保護委員会の通則ガイドライン 3-5-3-3 は「概ね3～5日以内」としている - この数字には規則ではなく
    ガイドラインを引用する）。第8条第2項：確報は 30 日以内、不正の目的によるおそれがある場合は 60 日以内。
    コードでは：ログから漏えいを検知し、その範囲（誰のデータか）を特定できるか（`owasp-web.md` A09）。
  - 第27条：第三者提供。第28条：外国にある第三者への提供 - 個人データを受け取る LLM プロバイダ、
    分析サービス、海外のクラウドリージョン。
  - 医療と健康のデータ：`reference/standards/medical.md` の業種別ガイドラインが上乗せで適用される。
- **番号法**（行政手続における特定の個人を識別するための番号の利用等に関する法律、通称：マイナンバー法。
  正規名 `Japan My Number Act`）：個人番号は法が認める目的（社会保障、税、災害対策）でのみ保有できる。
  人事 / 給与 / 税務システム以外にある `my_number` / `kojin_bango` のカラム、ログ行、API の項目は指摘事項とし、
  許容される箇所では暗号化とアクセスログの記録を確認する。
- **電気通信事業法の外部送信規律**（正規名 `Japan Telecommunications Business Act`、2023-06-16 施行）：
  タグや SDK（分析、広告、チャットウィジェット）を通じて利用者の情報を第三者に送信するサイトやアプリは、
  何を、誰に、なぜ送信するかを公表または通知しなければならない。コードでは：第三者のタグ / SDK を列挙し、
  公表ページまたは同意の手順がそれらに言及しているかを確認する。
- **HIPAA：** covered entities および business associates に適用される。現行規則では PHI の保存時暗号化は
  「addressable」（対応検討）仕様だが、実施しない場合は正当化が必要 - P1 として扱う。

## 重大度の目安
- 特別な種類または国民 ID のデータが平文で保存され到達可能 -> P0/P1。
- アカウント削除後も主要ストアに個人情報が残存 -> P1。文書化されたローテーションのあるバックアップにのみ残存
  -> P2。
- トラッキング SDK の同意ゲートの欠如 -> P2（子ども向け製品では P1）。
